# 前端需求分析

把原始产品输入（PRD/用户故事/原型图）整理为可供开发设计直接消费的前端需求说明。

## 流程

1. 通读输入材料，列出本次涉及的页面清单
2. 对每个页面：识别 UI 区块 → 做区块级的初步组件划分（只到区块，不做技术设计）
3. 逐个整理交互说明：每个可操作元素的行为、反馈、加载态
4. 边界条件清单：空态 / 错误态 / 极端数据 / 权限不足
5. 输出 `fe-req-{功能名}.md`，交互说明与边界条件逐条编号（REQ-001 起连续编号，编号由本 skill 统一发放，下游凭编号引用），章节固定为：页面清单 / 组件区块 / 交互说明 / 边界条件 / 开放问题

## 边界

- 不做技术选型、不设计状态管理（那是 fe-dev-design 的事）
- 不写测试用例（那是 fe-test-design 的事）
- 需求本身有矛盾时，记入"开放问题"，不擅自决定
