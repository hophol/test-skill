# Skill 评测加速策略（实测口径）

> 痛点：真实场景里 skill 评测非常慢——skill 有很多场景（多轮对话）、skill 本身要 agent 真执行、skill 依赖大量外部文件/知识才能得出结论。
> 本文把"慢"拆成三个可攻击的成因，给出六个加速手段；全部标注实测数据与已实现状态。

---

## 1. 慢在哪：三个成因与实测证据

| 成因 | 机理 | 本仓实测证据 |
|---|---|---|
| ① 场景多（轮×臂×重复） | 总时长 ≈ Σ(每轮 agent 执行) × 臂数 × 重复数 | clarify 2 轮×2 臂×3 次；全量 15 任务串行 ~8 分钟 |
| ② 要真执行 | 执行型 skill 的任务完成时间就是评测时间的下限 | webart 全量 600s 仍未完成（超时）；skill-up 评 frontend-design 240s 超时 |
| ③ 外部依赖 | 基线/无夹具时 agent 在空工作区乱找；产物断言要等全部文件写完 | 基线臂 26–97s 且行为漂移大（甚至开始建任务清单） |

**关键认知**：大部分评测问题根本不需要"任务完成"。**"skill 有没有被触发"在第 1 个工具调用时就已确定**——之后的全量执行对这个问题是纯浪费。

---

## 2. 六个加速手段

### 2.1 分层评测：不同的问题用不同的层（最高杠杆）

| 层 | 回答什么 | 成本 | 时延 |
|---|---|---|---|
| T0 静态 | 写得对不对、贵不贵（结构/预算） | 0 token | 秒级（14 skill 批量<1 分钟） |
| T1 路由 | 该不该触发、触发的是谁 | 1 轮 + 早停 | **秒级**（实测 5.1s） |
| T2 行为冒烟 | 触发后第一步对不对 | 1–2 轮 | 十秒级 |
| T3 全量行为 | 端到端做没做对 + lift | 全轮 × 2 臂 × N 次 | 分钟级（仅发版跑） |

规则：**日常改动只跑 T0/T1；T3 只在发版或改 description 时跑**。

### 2.2 路由早停（已实现：abort_when: skill_loaded）

对"是否触发"类断言，runner 流式盯事件文件，**一看到 Skill 工具调用就杀掉整棵进程树**：

~~~
实测对照（同一个问题：web-artifacts-builder 会不会被触发）
  全量执行：600s 超时未完成（CC17）
  早停路由：5.1s PASS（本特性的验收数据，tools=[Skill] 已捕获）
~~~

- 代价：拿不到 result 事件的 usage/成本（turn 里 cost=$0）——路由层不需要这些；
- 已知边界：若模型先调错 skill 再调对的，早停会停在第一个（对路由评测可接受，文档已注明）；
- 用法：用例里加 'abort_when: "skill_loaded"'（案例级或轮级），断言只留 must_call_skill。

### 2.3 基线复用（lift 的分母不用重跑）

**基线（without_skill）不随 skill 改动而变化**——改 SKILL.md 只影响 with_skill 臂。因此：

~~~
改 skill 后：
  node cc-eval.mjs run <case> --arms with_skill --repeats 3
  node cc-eval.mjs report        # report 聚合 out/ 里全部历史 run，
                                 # 混用旧基线 + 新技能臂计算 lift
~~~

注意：复用前提是**模型与配置没变**（报告里 requestedModel/observedModels 可核对）；换模型后必须重跑基线。

### 2.4 并发（已实现：--concurrency，CC16）

run 级并发（case×arm×repeat），轮内仍串行（同一会话）。实测 15 任务 8 分钟 → 166s（≈2.9×）。

### 2.5 外部依赖三件套（待实现）

- **夹具快照**：外部知识预置进 fixture（我们已这么做：PRD/需求文档随用例带）；skill-up 的 repo_fixture + git.apply_diff 是更强形态；
- **mock**：agentut 的 MockRule{tool, when[], output} 可把"真执行"换成"假返回"（写文件/跑命令类 skill 的 T2 层可用）；
- **回放**：DSH 仓的 llm-replay——录一次真实轨迹，之后零 token 复跑回归（适合"外部知识结论对不对"这类断言固定的场景）。

### 2.6 修复环子集（已实践，CC17 流程）

改 description 只复测"原失败 + 同族正例 + 相关负例"；配合 T1 早停，一轮修复环可以压到分钟级。

---

## 3. 加速后的一套日常流程

~~~
改了 SKILL.md 正文
  → T0 静态（秒）
  → T1 路由（受影响用例，每条 ~5s）
  → T2/T3 只跑该 skill 的行为用例 with_skill 臂（基线复用）
  → 发版日才跑全量两臂 × 3 次（166s @ 并发3）

改了 description
  → 同上，但 T1 必须全量触发集跑（这是路由的核心资产）
~~~
