# 基于工程实践的 Skill 评测方法论 v2

> 来源：Richard Wang 的"Agent Skill 的评测工程实践"文章框架 + 本仓 90 个 skill 的实测教训。
> 核心原则：评测是层层嵌套的——用例→验证条件→基线隔离→评分可信度。任何一层失败，上层全部作废。

---

## 设计原则

### 1. 用例必须有区分度（命中 Skill 的介入决策点）

**失败模式**：用例太简单，模型凭常识就能做对，有/无 Skill 通过率一样，评测跑了等于没跑。

**设计方法**：
- 先问"这个 Skill 在哪个决策点介入？"
- 选的用例必须命中这个决策点
- 简单用例上 Skill 的贡献在效率（token 省 80%+），不在正确性
- 正确性差异需要"必须搜索/必须用工具才能答对"的难用例

**我们的教训**：tdd-guide 的基线也能写测试，lift=1 来自"流程合规"不是"质量差距"。说明用例没命中 Skill 的介入点（TDD 流程 vs 直接写测试的结果差异）。

### 2. 验证条件拆细（结果/过程/格式三类分开）

**失败模式**：一个用例只有一个 pass/fail，退步了不知道哪个能力退步了。

**设计方法**：
- 每个用例至少 5 条验证条件
- 先列结果类（写入了什么、没写入什么）
- 再补过程类（是否搜索了、是否验证了、工具不可用时的行为）
- 最后加格式类（输出格式、文件格式）
- 过程类容易被忽略，但区分"碰巧对了"和"可靠地对"靠的就是它

**关键规则**：
- 蒙对了但没走规定流程 → 判失败（因为下次遇到不是常识的会错）
- 工具挂了选择停下来而不是瞎猜 → 判通过（行为可靠）

### 3. 基线物理隔离

**失败模式**："不加载 Skill"但模型自己搜索到了 skill 文件并读取。

**设计方法**：
- 每次运行放在独立目录，只暂存输入文件
- 项目里的 .claude/skills/、CLAUDE.md 等对执行 Agent 完全不可见
- 不管模型多主动，物理上接触不到 Skill 文件

**额外规则**：不要同时改 Skill 内容和切换模型。如果必须切换，在迭代记录里标注。

### 4. 从工具调用序列判定业务结果

**失败模式**：验证条件在解析 Agent 的总结文本。总结是给人看的，业务正确性在工具调用里。

**设计方法**：
- 不要求 Agent 写总结
- 从执行记录中的工具调用序列读业务结果
- Agent 可能操作全对但总结格式不对（不应该扣分）
- 也可能操作全错但总结漂亮（不应该加分）

### 5. 验证条件不能创造 Skill 没承诺的标准

**失败模式**：条件要求"中文名"但 SKILL.md 说"用最通用的指代"。模型选择不同导致条件时过时不过。

**设计方法**：
- 每条验证条件必须能追溯到 SKILL.md 中的明确承诺
- 如果 SKILL.md 没有明确说，验证条件不应该假设
- 发现这类 bug 时：删掉条件 + 在 SKILL.md 中补充明确说明，两层各自收敛

### 6. 评分可信度的信号

**假阳性信号**：基线 token 消耗很低（<200）但通过率很高（100%）——大概率评分器区分力不够。

**设计方法**：
- 验证条件要具体到"评分 Agent 必须在执行记录中找到证据"
- "关联了正确的实体"要拆成逐条指定名称
- "没有误挂"要做成显式的负面检查

## 新旧方法对比

| 维度 | 旧方法（我们之前的） | 新方法（文章框架） |
|---|---|---|
| 用例选择 | 挑"能跑通的" | 挑"命中 Skill 介入决策点的" |
| 验证条件 | 1-3 条子串匹配 | 5+ 条，分结果/过程/格式三类 |
| 蒙对了但没走流程 | 判通过（结果对了） | **判失败**（行为不可靠） |
| 工具挂了选择停下来 | 判失败（任务没完成） | **判通过**（行为可靠） |
| 基线隔离 | 不注入 skill 到 prompt | **物理隔离**（独立目录，skill 文件不可见） |
| 判定依据 | 最终回复文本的子串 | **工具调用序列**中的证据 |
| 评分假阳性检测 | 无 | 基线 token 低但通过率高 → 可疑 |

## 实施计划

用 us-breakdown skill（我们最熟悉的）构建一套完整的 v2 评测：

1. **区分度用例**：构造一个"必须用 parser 脚本才能正确拆解的复杂 US"——模型凭常识拆解会出错
2. **过程验证**：验证 agent 是否在写产物之前先跑了 parser 脚本（而不是肉眼看了源码后手工推演）
3. **降级测试**：让 parser 脚本不可用（比如删掉执行权限），验证 agent 是停下来报告还是瞎猜
4. **细粒度验证**：每个用例拆 5+ 条条件（结果 3 条 + 过程 1 条 + 格式 1 条）
5. **基线隔离验证**：确认基线臂的工作区里物理上没有 skill 文件
